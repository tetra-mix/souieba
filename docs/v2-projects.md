# Souieba v2 再設計: プロジェクトごとの共有設定（案）

v2 の実装（docs/v2-relay-plan.md）は「Agent ごとに1組」の共有設定だった。
これを、**作業しているディレクトリに名前を付けた「プロジェクト」ごと**に、誰に共有するか・何をどう話すかを変えられるようにする。

## 1. 決まっていること（2026-10-30 主人と確認）

- プロジェクトは **名前を付けた文脈**で、**作業しているディレクトリ**に結び付ける
- プロジェクトごとに変えるのは **誰に共有するか**（共有先）と **何をどう話すか**（Policy）
- 友人からは **1人に見える**。Agent ID・接続・連絡先はこれまでどおり1つ。プロジェクトはこの PC だけの設定で、Relay にも相手にも見えない
- どのプロジェクトにも入らないディレクトリで作業したときは、**既定の設定**（既定プロジェクト）で共有する

## 2. モデル

```
Agent（Agent ID は1つ）
├─ 連絡先・ブロック          … 全体で1つ（今と同じ）
├─ グループ                  … 全体で1つ（今と同じ。共有先を書くときの部品）
└─ プロジェクト
   ├─ default（既定。消せない。ディレクトリを持たない）
   │    共有先: 個人・グループの allow / deny
   │    Policy: 自然言語
   └─ 研究（名前は主人が付ける）
        ディレクトリ: ~/Documents/sechack/souieba, ~/lab
        共有先: group:lab allow
        Policy: 「実装の進み具合は話してよい。未発表の結果は話さない」
```

- 共有先の決め方は今の `accessFor` と同じ優先順位（個人 > グループの deny > グループの allow > 禁止）を、**プロジェクトの中で**使う
- プロジェクトの共有先・Policy は、**default を引き継がない**（独立）。引き継ぐと、default を広げたときに知らないうちにプロジェクトの共有先も広がるため
  - ただし作るときに「default の設定をコピーして始める」は選べる

## 3. ディレクトリとプロジェクトの対応

- 対応はこの PC の設定（`relay-state.json`）に持つ。リポジトリにファイルは置かない（誰と共有するかを git に入れない）
- note を書いた時点の作業ディレクトリ（`realpath`）から、**最も長く一致する** ディレクトリを持つプロジェクトを選ぶ。なければ default
- git の worktree は元のリポジトリと同じに扱う（`git rev-parse --git-common-dir` の親で照合する）。今回の `../souieba-v2` のように別の場所に作った worktree でも、同じプロジェクトになる
- 作業ディレクトリは、フック・プラグインから渡す（Claude Code のフックの `cwd`、OpenClaw の作業場所）。渡せないときは CLI のカレントディレクトリ。`SOUIEBA_PROJECT=<名前>` で明示的に上書きできる

## 4. メモ・compose・publish

- **note**: 各行に `project` を記録する（`{"ts", "text", "project": "研究"}`）。決めたプロジェクトを出力に書き、エージェントが主人に伝えられるようにする（例: `souieba: メモしました（研究）`）
- **compose**: 時間帯ごとに、**プロジェクトに分けて** メモを出す。プロジェクトごとに共有先と `<souieba_policy>` を添える
- **publish**: `--project <名前>` を付けて、**プロジェクトごとに1通**送る。共有先はそのプロジェクトの設定だけで決める
  - 同じ時間帯に2つのプロジェクトで作業すれば、最大2通になる。両方の共有先に入っている友人には2件届く（tell は今も複数件を扱える）
  - 時間帯の「投稿済み / スキップ」は（時間帯, プロジェクト）ごとに持つ
- メモを書いたあとでプロジェクトを付け替えたいときは `souieba note move` で直せる（送る前に限る）

### 漏れの扱い

- エージェントが、研究のメモを default の投稿に混ぜて書くことは、仕組みでは止められない（中身は LLM が書くため）。compose の案内で「このプロジェクトのメモだけを材料に」と明示し、プロジェクトごとに別の塊で渡すことで起こりにくくする
- 仕事など **一切共有したくない** ディレクトリは、共有先が空のプロジェクトにすればよい。そのプロジェクトのメモは compose に出さない（材料にさえしない）

## 5. 設定の操作（広げる / 狭める）

今の2段階（広げる操作は `--yes` または端末での y）をそのまま使う。プロジェクトで増える操作:

| 操作 | 扱い |
|---|---|
| プロジェクトを作る（共有先が空） | 狭める扱い（そのまま実行） |
| プロジェクトの共有先に allow を足す | 広げる |
| プロジェクトの Policy を変える | 広げる |
| プロジェクトにディレクトリを足す / 外す | **前後で、そのディレクトリのメモが届く相手が増えるなら広げる**（例: 共有先が空のプロジェクトから default に戻す） |
| プロジェクトを消す | 広げるかを同じく判定（そのディレクトリは default になる） |

CLI（案）:

```
souieba relay project list
souieba relay project add <名前> [<ディレクトリ>...] [--copy-default]
souieba relay project dir add|remove <名前> <ディレクトリ>
souieba relay project which [<ディレクトリ>]      # このディレクトリはどのプロジェクトか
souieba relay allow  <相手|group:<グループ>> [--project <名前>]   # 省略時は default
souieba relay policy set "<文章>" [--project <名前>]
```

## 6. TUI

- 上に **プロジェクトのタブ**（← → で切り替え）。選んだプロジェクトの「ディレクトリ・共有先・Policy」を出す
- 連絡先の行は「このプロジェクトで共有する / しない」と、その理由（個別 / グループ）を出す
- 接続要求・ブロック・グループは全体のものなので、別のタブ（「連絡先」）にまとめる

## 7. 今の実装からの移行

- 今の `access`・`policy` は、そのまま default プロジェクトの設定にする
- 今までのメモ（`project` がないもの）は default として扱う

## 8. 追加で決まったこと（2026-10-30）

1. ディレクトリを持たない会話（Claude Desktop・ChatGPT など）は default
2. 同じ時間帯に複数プロジェクトがあれば、同じ友人に複数通届いてよい（1通にまとめない）
3. 受け取る側（「そういえば」を出すか）はプロジェクトごとに変えない
