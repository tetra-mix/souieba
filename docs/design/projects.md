# プロジェクトごとの共有設定

共有設定は Person ごとに1組で、作業しているディレクトリに名前を付けた「プロジェクト」ごとに、誰に共有するか（共有先）と何をどう話すか（Policy）を変える。
このファイルは、プロジェクトのモデル、メモのプロジェクトの決め方、プロジェクトごとの投稿、共有を広げる操作の扱いを決める。エージェントに設定の変更を任せる仕組みは [delegation.md](delegation.md) に分けた。

## 1. モデル

```
人（Person ID は1つ。この PC のエージェントはすべて同じ設定を使う）
├─ 連絡先・ブロック          … 全体で1つ
├─ グループ                  … 全体で1つ（共有先を書くときの部品。この PC だけのもの）
└─ プロジェクト
   ├─ default（既定。消せない。名前も変えられない。ディレクトリを持たない）
   │    共有先: 個人・グループの allow / deny
   │    Policy: 自然言語
   └─ 研究（名前は主人が付ける）
        ディレクトリ: ~/Documents/sechack/souieba, ~/lab
        共有先: group:lab allow
        Policy: 「実装の進み具合は話してよい。未発表の結果は話さない」
        説明: どんな作業のプロジェクトか（任意。エージェントの推定に使う）
        acceptInference: エージェントの推定で入れてよいか（既定 true）
```

- プロジェクトは名前を付けた文脈で、作業しているディレクトリに結び付ける。結び付けたディレクトリ（`dirs`）は realpath にして持ち、git の worktree は元のリポジトリの場所に置き換える（`git rev-parse --git-common-dir` の親。bare リポジトリは置き換えない）。別の場所に作った worktree でも、元のリポジトリと同じプロジェクトになる。
- どのプロジェクトにも入らないディレクトリと、ディレクトリを持たない会話（Claude Desktop・ChatGPT など）は、メモのプロジェクトが決まらない場合の扱い（3 章の `unresolved`）に従い、既定は default になる。
- 同じディレクトリは1つのプロジェクトにしか付けられない（付けると、ほかのプロジェクトから外れる）。入れ子のディレクトリは別のプロジェクトにできる。照合は、メモを書いた場所に最も長く一致する結び付け先を持つプロジェクトを選ぶ。
- 友人からは1人に見える。ID・接続・連絡先は Person で1つで、プロジェクトはこの PC だけの設定として `relay-state.json` に持つ。Relay にも相手にも送らない。リポジトリにファイルは置かない（誰と共有するかを git に入れない）。
- 受け取る側（「そういえば」を出すか）は、プロジェクトでは変えない。
- 名前は表示名と同じ規則（1〜40文字、命令に見える文は不可）で、`default`・`既定` は使えない。プロジェクトは default を含めて50個まで、Policy は1000文字まで、説明は200文字まで（説明に命令に見える文は書けない）。

## 2. 共有先の決め方

プロジェクトごとの共有先は、個人（Person ID）とグループに `allow` / `deny` を付けたもの。誰に共有してよいかは次の優先順位で決める（`accessFor`）。この規則を、プロジェクトの中で使う。

1. 個人の設定があればそれに従う（グループの設定より優先）
2. 入っているグループの設定のうち、1つでも `deny` があれば禁止
3. 入っているグループのどれかが `allow` なら許可
4. どれもなければ禁止（既定）

- 共有先も Policy も、default を引き継がない。独立している。作るときに `--copy-default` で default の共有先と Policy を写して始めることはできる。
- プロジェクトを作った直後は共有先が空で、誰にも届かない（`--copy-default` を付けたときを除く）。
- 知らないプロジェクトには誰にも共有しない。
- 接続を解除・ブロックした相手は、連絡先・グループ・全プロジェクトの個人設定から消える。

## 3. メモのプロジェクトの決め方

メモごとに、次の順で先に当てはまったものを使う。どの手順で決めたかを `via` としてメモに記録する。

| 順 | 手順 | via | 入力 |
|---|---|---|---|
| 1 | 主人の規則: 環境変数 | `env` | `SOUIEBA_PROJECT=<名前>`（エージェントの起動時に主人が付ける）。ないプロジェクトなら、default に入れず断る（打ち間違いで広い設定に入らないため） |
| 1 | 主人の規則: ディレクトリ | `rule-dir` | `souieba note` を実行した場所（CLI のカレントディレクトリか `--cwd`）が、結び付けたディレクトリの中 |
| 1 | 主人の規則: MCP クライアント | `rule-client` | MCP の initialize の `clientInfo.name` を、`souieba mcp-client set <クライアント名> <プロジェクト>` で結び付けたもの |
| 2 | 会話ごとの指定（pin） | `pin` | 主人が「この会話は仕事」と言ったときだけ。MCP は `souieba_project_pin`（その MCP の接続のあいだ）、CLI・フックは `souieba project pin <名前> --session <会話の ID>` |
| 3 | 作業場所: 会話の作業ディレクトリ | `cwd` | フックが知らせた `cwd`（会話の ID ごとに覚える） |
| 3 | 作業場所: MCP の roots | `roots` | roots に対応したクライアントの `roots/list`（`file://` のもの。1.5秒で答えなければ使わない） |
| 4 | エージェントの推定 | `inferred` | CLI の `note --project-guess <名前>`、MCP の `souieba_note` の `project`。そのプロジェクトが `acceptInference`（既定 true）のときだけ。「推定」の印が付く |
| 5 | 決まらない | `default` / `hold` | 全体の設定 `unresolved`。`default`（既定）なら既定のプロジェクト、`hold` なら保留（主人が振り分けるまで送らない） |

主人があとで振り分けたメモは `via: owner` になる。

- 主人の規則（1）と作業場所（3）の違い: ディレクトリの照合は同じだが、1 は「メモを書いたコマンドが実際に動いている場所」、3 は「会話（セッション）単位で知らされた場所」。会話の指定（2）は 3 より強く、1 より弱い。主人が結び付けたディレクトリの中での作業は、そのディレクトリのプロジェクトになる。
- エージェントが言う作業ディレクトリは使わない。自己申告の場所も、MCP サーバ自身のカレントディレクトリ（作業場所ではない）も使わない。
- 会話の ID: Claude Code・Codex・Hermes Agent のフックは `session_id` を渡す（作業ディレクトリ `cwd` は Claude Code・Codex が渡す）。`souieba hook` がそれと作業ディレクトリを覚え（`person/sessions.json`。最後にフックが呼ばれてから24時間たった記録は消す）、手引きに「この会話の ID」を書いて、`souieba note --session <ID>` を使ってもらう。会話の ID が分からないエージェントでは、指定の代わりに `SOUIEBA_PROJECT` で起動してもらう。MCP は会話ごとにプロセスが分かれるので、pin はそのプロセスの中にだけ持つ。
- 指定は主人の言葉のときだけ。友人の近況や Narrator をきっかけに指定してはいけない（ツールの説明と手引きに書く）。
- 推定: プロジェクトに説明を付けると、エージェントへの手引き（フック・MCP）に「推定で選べるプロジェクト: 名前: 説明」として出る。`acceptInference: false` のプロジェクト（仕事など）は推定では選ばれず、手引きにも出ない。推定を受け付けなかったときは、その理由（プロジェクトがない・推定では選べない設定）を `note` の結果に返す。推定で入ったメモは compose・note・publish・sent・TUI で「推定」と出る。
- 振り分け: 保留のメモと、推定で決めて未投稿のメモ（どちらも48時間以内）は、`souieba review`・TUI の「保留と推定」タブで確かめ、`souieba note move <プロジェクト> [--held] [--note <時刻>] [--from <プロジェクト>] [--period <開始時刻>]` で付け替える。付け替えは未投稿のメモだけが対象。推定で入れたメモを同じプロジェクトへ「移す」操作は、主人がそのプロジェクトだと確かめたことになる（`via: owner`）。
- 保留のメモはプロジェクトを持たず（`project` を記録しない）、投稿の材料にならない。

## 4. メモ・compose・publish

- **note**: 各行に `project` と `via` を記録する（`{"ts", "text", "project": "研究", "via": "rule-dir"}`）。決めたプロジェクトを出力に書き、エージェントが主人に伝えられるようにする（例: `souieba: メモしました（プロジェクト: 研究）`）。default に決まったメモは、推定でなければ出力に書かない。`project` のないメモは default として扱う。
- **compose**: 時間帯（長さは `post-interval`。既定は1時間）ごとに、プロジェクトに分けてメモを出す。プロジェクトごとに、共有してよい相手・グループと `<souieba_policy>` を添える。プロジェクトが複数あるときは「その塊のメモだけを材料にする」と案内する。Policy がないプロジェクトには、作業の種類と課題までは書き、社名・未発表の情報・コードの細かい中身は書かないよう案内する。
- **publish**: `--project <名前>` を付けて、プロジェクトごとに1通送る。宛先はそのプロジェクトの共有先だけで決める（`--to` で絞れる）。同じ時間帯に2つのプロジェクトで作業すれば最大2通になり、両方の共有先に入っている友人には2件届く（tell は複数件を扱える）。存在しないプロジェクトへの publish は断る。
- 時間帯の「投稿済み / スキップ」は（時間帯, プロジェクト）ごとに持つ。キーは時間帯の開始時刻で、default 以外は `#<プロジェクト名>` を付ける。
- 送った近況のプロジェクトと「推定」の有無は、手元の `sent` に7日間残し、`souieba sent` で出す。Relay には送らない。
- プロジェクトの名前を変えると、メモと（時間帯, プロジェクト）の記録も付け替える。プロジェクトを消すと、そのディレクトリと未投稿のメモは default になる。存在しないプロジェクトのメモは default として扱う。

### 漏れの扱い

- エージェントが、研究のメモを default の投稿に混ぜて書くことは、仕組みでは止められない（投稿の中身は LLM が書くため）。compose の案内で「その塊のメモだけを材料に」と明示し、プロジェクトごとに別の塊で渡すことで起こりにくくする。
- 一切共有したくないディレクトリは、共有先が空のプロジェクトにする。そのプロジェクトの（時間帯, プロジェクト）は、compose・tell・note の結果で投稿待ちを数えるときに自動でスキップにし、メモを compose に出さない（材料にもしない）。あとで共有先を足しても、スキップにした時間帯は送らない。
- ただし、どのプロジェクトでもまだ誰にも共有していない（使い始めの）ときは、共有の設定を促すため、compose に出して「スキップして、主人に共有の設定を頼む」と案内する。

## 5. 共有を広げる操作と狭める操作

共有の設定を変える操作は、CLI・TUI・MCP で同じ部品（`relay-ops/`）を使う。どの操作も、まず「何が変わるか」（変更の内容）を組み立て、共有を広げるかを判定してから実行する。

- **狭める操作**（reject・disconnect・block・deny・グループから外す・推定を断る・保留にする など）は、そのまま実行する。間違っても漏れない。
- **広げる操作**は2段階にする。
  - 端末（TTY）から実行したときは、変更の内容を見せて y/N で聞く。
  - 端末の外（エージェント）から実行したときは、`--yes`（MCP は `confirm: true`）がなければ、変更の内容だけを出して止まる（終了コード 3）。エージェントはその内容を主人に見せ、主人が会話で同意したら `--yes` を付けて実行し直す。
  - TUI は画面の中で y/n を聞く。
- 端末の外で変えた設定は記録し（`changeLog`。50件まで）、次の `tell` で主人に知らせる。だまされたエージェントに設定を変えられても、主人が気づけるようにするため。
- 主人が範囲と期限を決めて任せた範囲の中なら、広げる操作も `--yes` なしで実行できる（[delegation.md](delegation.md)）。

### 広げるかの判定

基本は、変える前後で「共有してよい相手の集合」が増えるか。Policy は意味の判断に使うもので、機械的には狭めたか広げたか分からないので、変えるときはいつも広げる扱いにする。

| 操作 | 扱い |
|---|---|
| connect・accept・unblock | 広げる（共有には別に allow が要る） |
| reject・disconnect・block・nickname | 狭める |
| allow・reset・グループにメンバーを加える | 届く相手が増えるなら広げる |
| deny | 狭める |
| グループから外す・グループを消す | 届く相手が増えるなら広げる（`deny` を付けたグループから外す・消すときに起きうる） |
| policy set / clear | いつも広げる |
| プロジェクトを作る | 作るだけでは届く相手は変わらないので、そのまま実行。ディレクトリを付けて作るときは、そのディレクトリのメモが届く相手が増えるなら広げる（`--copy-default` で共有先を写したときなど） |
| プロジェクトにディレクトリを付ける・外す | 前後で、そのディレクトリのメモが届く相手が増える、または届く先の Policy が変わって届く相手がいるなら広げる（例: 共有先が空のプロジェクトから default に戻す） |
| プロジェクトを消す | 同じ判定（そのディレクトリと未投稿のメモは default になる） |
| プロジェクトの名前を変える | 狭める（届く相手は変わらない）。メモ・投稿済みの記録・任せた範囲も付いていく |
| `project describe` | 推定を受け付けるプロジェクトで、届く相手がいれば広げる（推定で入るメモが変わりうる）。説明を消すのは狭める |
| `project inference on` | そのプロジェクトに届く相手がいれば広げる。`off` は狭める |
| `mcp-client set` / `unset` | 決まらないときや前の規則より届く相手が増えるなら広げる |
| `unresolved hold` | 狭める |
| `unresolved default` | 保留から戻すとき、default の共有先がいれば広げる |
| `project pin` | 指定しないときより届く相手が増えるなら広げる。外す（unpin）のは狭める |
| `note move` | 移した先で届く相手が増えるなら広げる |

ディレクトリやメモを Policy の違うプロジェクトへ移すのは、届く相手がいるなら広げる扱い。

## 6. 設定の入口

### CLI

```
souieba project list
souieba project add <名前> [<ディレクトリ>...] [--copy-default]
souieba project dir add|remove <名前> <ディレクトリ>...
souieba project which [<ディレクトリ>]                  # このディレクトリはどのプロジェクトか
souieba project describe <名前> <説明>
souieba project inference <名前> on|off
souieba project pin <名前> --session <会話の ID>        # 外すのは project unpin --session <会話の ID>
souieba project rename <名前> <新しい名前>
souieba project delete <名前>
souieba allow|deny|reset <相手|group:<グループ>> [--project <名前>]   # 省略時は default
souieba policy [set "<文章>" | clear] [--project <名前>]
souieba mcp-client [list | set <クライアント名> <プロジェクト> | unset <クライアント名>]
souieba unresolved default|hold
souieba review                                          # 保留のメモと、推定で決めたメモ
souieba note move <プロジェクト> [--from <プロジェクト>] [--period <開始時刻>] [--held] [--note <メモの時刻>]
```

コマンドの一覧は `apps/cli/src/commands/catalog.ts` が唯一の定義で、ヘルプと文書中のコマンド例の検査はここから作る。`souieba status` は、連絡先・グループ・プロジェクトごとの共有先と Policy・メモの振り分けの規則・任せている範囲を一覧する。

### MCP

シェルのない MCP クライアント（Claude Desktop など）のために、同じ操作を MCP のツールとして出す。中身は CLI と同じで、同じ2段階（`confirm: true`）・同じ記録を使う。

- `souieba_relay_status`（見る）・`souieba_relay_contact`・`souieba_relay_access`・`souieba_relay_group`・`souieba_relay_policy`・`souieba_relay_project`（プロジェクトと振り分けの規則）・`souieba_relay_delegation_revoke`
- `souieba_project_pin`（この会話の指定）、`souieba_note` の `project`（推定）

### TUI

`souieba ui` は、主人が自分の目で見て直接操作する画面で、エージェントを通さない。

- 上にタブを並べる: default・ほかのプロジェクト（名前順）・「連絡先」・「保留と推定」。左右キーで切り替える。
- プロジェクトのタブは、共有方針・説明・推定の可否・ディレクトリ・共有先を出す。連絡先の行は「共有する / しない」と、その理由（個別 / グループ）を出す。
- 「連絡先」のタブは、全体のもの（接続要求・呼び名・グループ・ブロック）をまとめる。
- 「保留と推定」のタブは、保留のメモと推定で決めたメモ、MCP クライアントの規則、決まらないときの扱いを出し、メモの振り分けができる。
- 任せる範囲の表示と操作もここにある（[delegation.md](delegation.md)）。

## なぜこうしたか

- **プロジェクトは作業単位で、ID は人ごと。** 共有してよい相手や話してよいことは、端末やエージェントではなく「どんな作業か」で変わる。最初の v2 はエージェントごとの設定だったが、それをやめ、人の鍵を1つにして、エージェントはその人の端末として扱う。友人からは1人に見え、プロジェクトの違いは見えない。
- **プロジェクトは default を引き継がない。** 引き継ぐと、default を広げたときに、知らないうちにプロジェクトの共有先も広がるため。
- **メモのプロジェクトは、宣言を先に、推定を後にする。** 主人が結び付けた規則と主人の言葉による指定は決定的で、エージェントの推定は LLM の判断なので誤りうる。誤った推定で届く相手が増えないよう、推定は最後にし、プロジェクトごとに断れる（仕事などは `acceptInference: false`）。推定で入ったメモには印を付けて、主人があとから確かめて直せる。
- **エージェントが言う作業ディレクトリは使わない。** 自己申告は誤りや、だまされた結果でありうる。フックや MCP が実際に知らせた場所、または主人の指定だけを使う。
- **決まらないメモに「保留」を用意した。** 主人が振り分けるまで誰にも送らない選択肢があれば、決まらないメモが default の共有先に流れることを避けられる。
- **共有先が空のプロジェクトは自動でスキップする。** 共有したくない作業のメモを、毎回 compose で聞かれたり、材料にされたりしないようにするため。
- **広げる操作だけを2段階にする。** 狭める操作は間違っても漏れないので止めない。広げる操作は、エージェントが自分の判断で行わないよう、主人の同意の手順を必ず踏ませる。`--yes` はその段差で、同じユーザー権限で動くプログラムへのセキュリティ境界ではない。
- **推定のための説明は、短く、命令に見えない文だけにする。** 説明はエージェントへの手引きに入るので、指示に見える文は断り、200文字に絞る。
- **同じ時間帯でも、プロジェクトごとに別の投稿にする。** 共有先と Policy がプロジェクトごとに違うので、1通にまとめると、共有先の違うプロジェクトの内容が混ざる。

- `packages/sdk/src/project.ts` — ディレクトリの照合（`canonicalDir`・`matchProject`）、メモのプロジェクトの決め方（`resolveNoteProject`）、会話ごとの指定と作業ディレクトリ（`SessionStore`）
- `packages/sdk/src/relay-state.ts` — 状態の型（`Project`・`RelayState`）、共有先の決め方（`accessFor`）、宛先の決定（`resolveTargets`）

- `apps/cli/src/relay-tui.ts` — TUI
